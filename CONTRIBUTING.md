# Contributing

Thanks for looking. This is an unfunded open-source project — see
[Resourcing](README.md#resourcing) for what that means in practice.

## Developer Certificate of Origin

Every commit must carry a `Signed-off-by` line matching the author:

```
Signed-off-by: Your Name <your@email.example>
```

`git commit -s` adds it for you. CI rejects commits without it.

Enable the repository hooks once per clone so an unsigned commit is refused where you make
it, rather than after it is pushed — fixing it at that point means rewriting published
history:

```
git config core.hooksPath .githooks
```

This is the [Developer Certificate of Origin 1.1](https://developercertificate.org/): by
signing off you state that you wrote the contribution, or have the right to submit it under
the project's licence. **We do not ask for a CLA.** You keep the copyright in your
contribution. That also means the project cannot unilaterally relicense your work, which is
deliberate — the open components carry a public commitment never to be relicensed, and that
commitment is worth more if it is structurally true rather than merely intended.

### History before DCO adoption

Commits made before this check was added carry no sign-off. All of them have a single author,
who affirms that the Developer Certificate of Origin applies to that work as though it had been
signed. Those commits were already pushed, so they have been left intact rather than rewritten.
Everything from the DCO check onward is enforced in CI.

## Contributing an attack class

The most valuable contribution is a tamper the suite does not catch.

Add it to [`redteam/redteam.mjs`](redteam/redteam.mjs) as a new entry in the `attacks` array,
declaring the outcome you observe. Each entry states `expect: 'detected' | 'undetected'`, and
the suite exits non-zero when an observation changes — so a new class that passes verification
turns the build red, which is the point.

```bash
npm install
npm test
```

Contributions are credited by name in the suite and in the release notes. While the project is
unfunded there is no cash award; that is stated plainly rather than implied.

## Changing requirements

`requirements/*.json` is the source of truth; `MATRIX.md` and `PLAN.md` are generated by
`npm run backlog`. The validator rejects any requirement without a release-notes section behind
it, and any release-1.0 requirement not assigned to a milestone. **A requirement cannot exist
without a promise behind it** — so if you are adding one, say which line of the release notes
it serves, or change the notes first.

## Scope guards

Sixteen requirements say what this project must *not* do: no blocking of agent actions, no
tamper-proof claims, no compliance certification, no fail-closed option. They are listed in
[requirements/MATRIX.md](requirements/MATRIX.md) under *Scope guards*. A change that crosses one
will be declined even if it works, so please raise it as an issue first.
